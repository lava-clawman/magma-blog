# Daily Review 2026-03-16

- Related: [[Second Brain Operating System]], [[Second-Brain-Integration-Plan-v1]], [[Task Management]], [[FlashNotes]]

## 今日关键事项
- 明确了 [[OpenClaw]] 多 agent 共享记忆的边界：默认设计是按 agent 隔离 workspace、session、auth 与 memory，不存在官方“一键全局共享 MEMORY”的开关。
- 形成了 3 种共享记忆实现路径，并给出适用场景：
  - 共用同一 workspace：适合同一人格的多入口。
  - 独立 workspace + 共享 memory 文件注入：适合多角色协作下的公共背景同步。
  - 独立 agent + 中心化 memory service / memory agent：适合更强边界与可控性。
- 输出了面向实践的推荐方案：优先采用“独立 workspace + shared-memory 注入”，兼顾隔离性与共享上下文能力。

## 决策与变更
- 决策：将“共享记忆”定义为**共享文件/共享知识层**，而不是共享 session 历史；各 agent 对话历史仍保持独立。
- 决策：不建议复用同一个 `agentDir` 来共享认证；如需共享认证，单独复制 `auth-profiles.json`，避免会话与凭证冲突。
- 决策：若只是不同渠道入口但本质是同一个助手，可直接让多个 agent 指向同一 `workspace`；若目标是多角色协作，则避免直接共写同一套人格与记忆文件。
- 认知澄清：sub-agent 不是完整继承主 agent 全量人格/记忆，只会拿到有限 bootstrap 上下文，不能视为天然“共享大脑”。

## 错误与改进
- 修正了一个常见误区：**共享 `[[MEMORY]]` 不等于共享整段对话历史**；session 仍按 `agent` 分离存储。
- 修正了另一个风险点：**不要通过共用 `agentDir` 来实现“共享”**，这会带来 auth 与 session 污染风险。
- 形成更稳妥的设计建议：若需要公共知识，应优先共享受控的记忆层或知识源，而不是让多个 agent 同时自由读写同一整套工作区。
